# AliProfi P3 Load Profiler

## 📝 Описание (на русском)

**P3 Load Profiler** — бесплатный плагин для WordPress, который показывает, **сколько ресурсов сайта потребляет каждый плагин**: время генерации страницы, пиковую память PHP и SQL-запросы к базе данных. Работает по принципу легендарного P3 (Plugin Performance Profiler): прогоняет выбранные страницы **по одному плагину за раз**, сравнивает результат с «чистой» базовой линией и строит рейтинг самых тяжёлых плагинов, чтобы вы знали, что оптимизировать или чем пожертвовать.

Разработан для сайта [Алиэкспресс для профессионалов](https://aliprofi.ru).

### 🔧 Возможности

- **Изолированные замеры**: каждый проверяемый плагин включается отдельно, поэтому видно его личный вклад, а не общую нагрузку сайта.
- **Три метрики на каждый плагин**: время загрузки страницы (мс), пиковая память (КБ) и число/время SQL-запросов.
- **Автоматическая базовая линия**: сайт без проверяемых плагинов + повторный проход после теста, чтобы компенсировать прогрев кешей.
- **Медиана по нескольким прогонам** — случайные выбросы не искажают картину.
- **Дельты и доля вклада**: насколько плагин замедляет сайт относительно базы и какой процент общей нагрузки даёт.
- **Оценка серьёзности**: `Высокая` / `Средняя` / `Норма` / `Ошибка` с наглядными барами и рекомендациями.
- **Отчёт по каждой странице и прогону**, экспорт результатов в **CSV** (разделитель `;`, BOM — корректно открывается в Excel и «МойОфис»).
- **История сканов** с возможностью открыть или удалить любой отчёт.
- **Полная изоляция от ваших данных**: плагин не меняет настройки сайта, не трогает контент и сам возвращает список активных плагинов после теста.
- **Интерфейс полностью на русском**, без внешних зависимостей и автозагрузчиков — один лёгкий плагин на чистом PHP.

### 📊 Что именно измеряется

| Метрика | Как считается |
| --- | --- |
| Время, мс | От старта WordPress до завершения запроса (`microtime`) |
| Пиковая память, КБ | `memory_get_peak_usage()` за запрос |
| SQL-запросы | Количество запросов через `$wpdb` и суммарное время выполнения (через `SAVEQUERIES`) |
| Доля вклада | `max(0, дельта) / (время базы + сумма дельт)` |
| Серьёзность | Высокая: ≥ 120 мс, ≥ 60 запросов или ≥ 2× базы; Средняя: ≥ 60 мс или ≥ 25 запросов |

### ⚙️ Как это работает

1. Плагин ставит в `wp-content/mu-plugins/` загрузчик `plp-loader.php`. Он загружается **раньше всех обычных плагинов** и на время замера подменяет список активных плагинов.
2. При старте скана показывается один тестовый URL в браузере: сначала сайт без проверяемых плагинов, затем профайлер + один проверяемый плагин, и так для каждого.
3. Каждый ответ запоминает время, память и SQL-запросы; после серии прогонов считается медиана и дельта к базовой линии.
4. В конце исходный список активных плагинов **восстанавливается автоматически** — даже если проверяемый плагин попытался отключить себя, увидев, что «пропала» его зависимость.
5. Результаты сохраняются в собственные таблицы (`wp_plp_scans`, `wp_plp_results`) и остаются доступными в истории.

### 📦 Установка

**Вариант 1 — ZIP:**

1. Скачайте архив из [Releases](https://github.com/aliprofi/plugin-load-profiler/releases) или соберите сами из исходников.
2. WordPress → **Плагины → Добавить новый → Загрузить плагин** → выберите ZIP → **Установить** → **Активировать**.

**Вариант 2 — вручную:**

```bash
cd wp-content/plugins
git clone https://github.com/aliprofi/plugin-load-profiler.git
```

1. Убедитесь, что в папке `wp-content/plugins/plugin-load-profiler` находится файл `plugin-load-profiler.php`.
2. Админка WordPress → **Плагины** → активируйте **P3 Load Profiler — профайлер плагинов**.

После активации в меню появится пункт **«Профайлер»**.

### 🛠 Использование

1. Откройте **Профайлер** в левом меню.
2. Отметьте плагины для проверки (свой профайлер в списке отсутствует — его исключать не нужно).
3. Укажите количество прогонов (1–10) и страницы для замера — по одной в строке. Если оставить поле пустым, используется главная страница. За раз можно проверить до 50 плагинов и до 5 URL.
4. Нажмите **«Запустить тест»** и не закрывайте вкладку: профайлер сам по очереди откроет страницы.
5. По завершении откроется отчёт: база, таблица плагинов с барами, детали по каждому прогону и кнопка **«Скачать CSV»**.
6. Тест можно **прервать** — активные плагины всё равно будут восстановлены.

> Совет: запускайте замеры на сайте без тяжёлого кеширования или с очищенным кешем, а страницы выбирайте типовые — главную, каталог, запись.

### ⚠️ Важно знать

- Замеры выполняются **от вашего имени** через браузер, поэтому тестовая страница должна быть доступна без пароля (или используйте публичные страницы).
- Запросы админ-панели (`admin-ajax.php`, `wp-admin`) не изолируются — измеряется фронтенд вашего сайта.
- Плагины, которые при активации создают собственные mu-plugins или файлы, могут оставить служебные следы.
- Список активных плагинов, сохранённый на момент старта, восстанавливается полностью; плагины, отключённые вами до скана, обратно **не** включаются.
- Активные сканы старше 3 часов автоматически помечаются прерванными, а список плагинов восстанавливается. Старые отчёты удаляются по сроку хранения (по умолчанию 30 дней).

### 🛠 Требования

- WordPress 6.0+
- PHP 7.4+ (проверено на PHP 8.6)
- Права администратора (`manage_options`)
- Возможность записи в `wp-content/mu-plugins/` (обычно есть; если нет — профайлер покажет предупреждение и подскажет, как исправить)

### 🔐 Безопасность

- Все действия в админке защищены capability `manage_options` и nonce.
- Запросы к БД выполняются только через `$wpdb->prepare()`.
- Тестовые URL принимаются только для хоста самого сайта (без внешних доменов).
- Токен доступа к активному скану — 128-битный, сравнение через `hash_equals()`.
- При удалении плагина через «Удалить» его таблицы, настройки, cron-задача и mu-загрузчик удаляются.
